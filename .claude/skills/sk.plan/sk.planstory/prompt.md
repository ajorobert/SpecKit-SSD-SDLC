# sk.planstory
Creates the technical implementation plan for **one project** within the active story.
Role: lead | Level: story (project-scoped)

Internal sub-skill — invoked by sk.plan orchestrator (once per impacted project). Do not invoke
directly. The orchestrator passes the target `{ProjectName}`.

## Path Resolution (per story-lifecycle.md §3–§4)
Resolve `STORY_DIR` from session.yaml `story_dir`. Output goes to `STORY_DIR/03-plan/{ProjectName}/`.
Legacy fallback (no story_dir): `specs/intents/{intent}/units/{unit}/stories/{story-id}/plan.md`.

## Input Artifacts
STORY_DIR/03-plan/planning-brief.md (if generated by orchestrator)
STORY_DIR/02-design/architecture.md (required)
STORY_DIR/02-design/database-design.md
STORY_DIR/02-design/ui-model.md (if exists — frontend projects only)
STORY_DIR/02-design/api-spec.json (machine contract)
STORY_DIR/02-design/projects/{ProjectName}.md (this project's design impact)
STORY_DIR/01-story/ (story.md, requirement.md, acceptance-criteria.md)
.specify/memory/projects/{ProjectName}/{tech-stack,coding-standards}.md
.specify/memory/standards/tech-stack.md (shared fallback)

## Steps
1. Verify `02-design/architecture.md` exists — if missing: STOP, remind orchestrator to run sk.design first.
2. [REFINE MODE] if `03-plan/{ProjectName}/plan.md` exists, [CREATE MODE] if not.
3. Write `STORY_DIR/03-plan/{ProjectName}/` (five files, per story-lifecycle.md §2):
   - **`plan.md`** — technical approach, component breakdown (build order; for frontend follow
     `ui-model.md`), data-layer changes (ref `database-design.md`), API changes (ref `api-spec.json`),
     dependencies on other projects, risks/open questions. Reference `architecture.md` + the
     project's design-impact file explicitly.
   - **`tasks.md`** — ordered, granular developer tasks (TDD order: test tasks before impl).
   - **`checklist.md`** — completion checklist / definition-of-done + checkpoint status header.
   - **`jira-subtask.md`** — proposed Jira sub-tasks (title + estimate + parent).
   - **`estimation.md`** — effort per task + total (story points or ideal-hours) + assumptions.

## Output Artifacts
STORY_DIR/03-plan/{ProjectName}/{plan,tasks,checklist,jira-subtask,estimation}.md
(Legacy fallback: specs/intents/{intent}/units/{unit}/stories/{story-id}/plan.md)

## Quality Bar
- Explicit reference to 02-design/architecture.md and 02-design/projects/{ProjectName}.md
- Cross-project dependencies honored per planning-brief.md
- Tech stack decisions justified against the project's tech-stack.md
- No contradictions with architecture.md
- If ui-model.md exists: plan's component breakdown and state decisions reference it and do not contradict it
- All five plan files written for the project
