# Jira Component → Project Map
Loaded by: sk.story (Jira mode), sk.design (project-scoping)
Updated by: humans (project onboarding) — never generated by a skill

This file is the **single, configurable source of truth** that maps a Jira issue's
**Components** to the internal project name(s) used across the spec pipeline. Skills MUST
read the mapping from here — component names and project names are NEVER hardcoded in skill
logic. Add, rename, or remove rows here when the Jira project structure changes.

The project names in the right column MUST match the project names used everywhere else in
the pipeline: `.specify/memory/projects/index.md` (project router), `unit-brief.md` →
Impacted Projects, and the `02-design/projects/{Project}.md` design page file names.

## Mapping
Format: one row per Jira Component. Matching is **exact and case-insensitive** on the
Jira Component name. Edit the rows below to match this workspace.

| Jira Component   | Project Name   | Type     |
|------------------|----------------|----------|
| TAGIN-API        | Backend.API    | Backend  |
| TAGIN-CONSOLE    | Admin.Panel    | Frontend |
| CUSTOMER-PORTAL  | Customer.Web   | Frontend |
| VENDOR-APP       | Vendor.App     | Mobile   |

## Rules
- A single Jira Component maps to exactly one Project Name.
- Multiple Components on one issue → the union of their mapped Project Names (de-duplicated).
- A Component present on the issue but ABSENT from this table is **unmapped**: it is reported
  as a warning and skipped — it never becomes a project, and it never silently blocks the run.
- If the issue has no Components at all, no project is detected (see sk.story: the `## Project`
  section is then omitted from story.md).
